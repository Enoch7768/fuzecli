# Security

FuzeCLI takes workspace safety, provider credentials, local API access, and generated changes seriously.

## Reporting a vulnerability

Please do not disclose a suspected vulnerability in a public GitHub issue.

Use GitHub's private security reporting facilities for this repository when available. If private reporting is not available, contact the FuzeCLI maintainers privately through GitHub with enough information to reproduce and assess the issue.

Do not include API keys, passwords, private keys, personal data, or other secrets in a report.

## What to include

A useful security report includes:

- affected version or commit;
- affected component or endpoint;
- reproduction steps;
- expected and observed behavior;
- security impact;
- relevant logs or minimal proof of concept with secrets removed.

## Response expectations

Reports are reviewed by the maintainers. The project may request additional reproduction information, assess affected versions, prepare a fix, and document the issue after a coordinated resolution.

There is no guaranteed response time or bounty program.

## Security documentation

See [docs/SECURITY.md](docs/SECURITY.md) for the current security model, workspace isolation rules, API protections, credential handling, recovery behavior, and known threat-model limitations.

For contribution and community expectations, see [CONTRIBUTING.md](CONTRIBUTING.md) and [CODE_OF_CONDUCT.md](CODE_OF_CONDUCT.md).
