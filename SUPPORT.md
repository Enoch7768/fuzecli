# Support

## Before asking for help

Check the project documentation first:

- [README.md](README.md)
- [CONTRIBUTING.md](CONTRIBUTING.md)
- [docs/](docs/README.md)
- [docs/WEB.md](docs/WEB.md)
- [docs/API.md](docs/API.md)
- [docs/TERMINAL.md](docs/TERMINAL.md)
- [docs/MCP.md](docs/MCP.md)
- [docs/SECURITY.md](docs/SECURITY.md)

Run the diagnostic command when possible:

```powershell
aicli doctor
```

Also include the FuzeCLI version and the relevant operating-system details when reporting a reproducible problem.

## Bug reports

Use GitHub Issues for reproducible bugs that are not security vulnerabilities.

A useful report should include:

- FuzeCLI version or commit;
- Windows version;
- exact command or workflow;
- expected behavior;
- actual behavior;
- relevant error output;
- minimal reproduction steps;
- whether the problem occurs consistently.

Remove API keys, credentials, private paths, personal information, and other sensitive data before posting.

## Feature requests

Feature requests should explain:

- the problem being solved;
- who is affected;
- the proposed workflow;
- why the existing behavior is insufficient;
- compatibility or security considerations.

Requests are evaluated against FuzeCLI's local-first architecture, workspace safety, maintainability, and user experience.

## Security issues

Do not report security vulnerabilities in a public issue.

Follow [SECURITY.md](SECURITY.md) and [docs/SECURITY.md](docs/SECURITY.md) for security reporting guidance.
